# Touch CPU check — 2026-11-01

Native engine, Release `clang++ -O3 -std=c++17 -fno-builtin -fno-exceptions`, 48 kHz, 64-frame callbacks. Five interleaved trials per workload and variant (shipping 0.1.4; candidate Touch 0, 50, 100%). Life 100% throughout; 0.5 s warm-up plus 2 s measured. Median thread CPU as a percentage of one core:

| Workload | 0.1.4 | Touch 100% |
| --- | ---: | ---: |
| idle | 0.928% | 0.941% |
| init_single | 2.013% | 2.039% |
| paris_triad | 5.510% | 5.582% |
| master28 | 14.167% | 14.045% |
| master28_aftertouch | 13.990% | 13.827% |
| master_changes | 14.644% | 14.540% |
| master28_2x | 26.209% | 25.639% |
| master28_4x | 50.090% | 49.485% |

The selected response stays close to the previous CPU cost. These differences do not establish an optimization. Touch adds one 200 Hz shared performer control; it adds no per-reed oscillator or audio filter. Low-velocity key travel can keep the existing vent calculations active longer than before.

All eight Touch-zero workload audio hashes equal the shipping engine, including Life 100%. These workloads use velocity 100; they do not test the deliberately changed low-velocity map. All variants were finite.

For the selected Touch 100% variant, no callback exceeded its 1.333 ms budget in measured thread time in these trials. Wall time had five exceedances across the six default-quality workloads and one at 4x. Other variants had thread deadline exceedances, including at 2x; the raw record is retained. This is not a Reason CPU reading, target-chip measurement, or deadline guarantee.

External evidence: `diagnostics/respira-touch-model-20261101/{cpu-raw.json,cpu-summary.json,cpu_probe.cpp,benchmark_touch.py}`. No other task-owned build or audio render ran during the timing trials. The native CpuBudget suite is recorded separately with the final build.

Additional slow-pallet stress: Master chords changed every 60 ms at velocity 8, 48 kHz / 64 frames / 1x, five alternating trials. baseline: 20.657% of one core, 3 thread deadline exceedances; candidate: 24.234% of one core, 3 thread deadline exceedances. Both were finite. This deliberately stresses moving valves; it is not a normal soft-note performance or an audibility claim. Raw record: `cpu-soft-raw.json`.

In the slow-key stress the same new playing model without caching used 25.903% of one core; the final cache uses 22.324% (13.8% less). The longer physical valve movement still costs more than the older short-travel model.

All eight ordinary workload hashes, the slow-key stress hash, the selected C WAV and twelve two-second dynamic sequences across four rates / three quality paths are bit-identical before and after caching. The latter include register changes, half-open keys and quality changes mid-note.
