# Life CPU measurements - 2026-11-01

Native engine only, Apple M1 Max / AppleClang 21.0.0, C++17 Release -O3 -fno-builtin. Each process warms up for 0.5 s and measures 2 s at 48 kHz / 64 frames. Five interleaved trials per variant, alternating order. Median total thread CPU is reported as percent of one core. Legacy is the frozen 0.1.3 candidate-probe; current variants use identical preset controls except Life. Different pressure can alter active reed work, so these figures do not isolate the cost of the motion generator.

Life 100% stays close to the previous engine in these workloads; this is not a demonstrated CPU speedup. Its low-rate motion and pickup geometry add no new per-reed solver, delay network, allocation or per-sample trigonometry. Life 0% matches all eight legacy benchmark audio hashes for these continuous-note workloads. Rest-turn behavior intentionally differs on the separately tested rest fixtures.

All default-quality Life 100% trials had zero thread-CPU blocks over the 1.333 ms deadline. The aftertouch workload had 13 wall-time exceedances; they remain in the evidence. At 2x, Life 100% had five thread-CPU exceedances; at 4x, 17. These optional stress modes are not deadline-free. Other variants also had wall and occasional CPU exceedances; no failed run was discarded. The standard Respira.CpuBudget test passed separately. Native figures exclude wrapper, Reason scheduling and SDK target translation. No host CPU guarantee is made.

Full per-block timing summaries, hashes, nonfinite checks and raw trial records are retained outside the public repository in diagnostics/respira-life-model-20261101/cpu-{raw,summary}.json.
